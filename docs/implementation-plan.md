# 赛题实现与验收计划

## 当前状态

- Windows 开发、GitHub SSH 推送、Ubuntu SSH 拉取已跑通。
- Compose 的 Nginx Web 入口已可通过公网 80 访问（用户截图确认）。
- backend 已实现真实 Suricata 离线任务、事件入库、API、角色授权及规则快照。
- 四类攻击、九场景真实自验及独立空数据卷验收已完成；详细交付缺口见 delivery-checklist.md。

## 第一阶段：真实检测闭环（优先完成）

1. 定义第一个 HTTP 攻击场景的 ground truth：SID、协议、地址、端口、时间窗。
2. 生成包含完整 TCP 会话的自建 pcap；流量仅离线生成，不向公网目标发送。
3. 添加 Suricata IDS 配置、自定义规则，先用 `suricata -T` 验证，再离线回放。
4. 替换 backend 占位服务：Python API、SQLite 持久化、任务及事件模型。
5. 每个回放任务使用独立输出目录，归一化 alert/flow/dns/http/tls；保留原始 JSON 和入库时间。
6. 页面通过 `/api` 展示真实告警、任务状态；空库显示空状态。

验收：提交一个 pcap 后，可从任务定位到真实告警、原始 EVE 事件和关联 flow；重放互不污染；重启数据库记录仍在。禁止用前端写死数据替代检测结果。

## Must 项验收清单

| 题目项 | 验收内容 |
| --- | --- |
| M1 流量接入 | 新 pcap 可导入、回放、查看失败原因 |
| M2 检测引擎 | Suricata IDS、自定义规则至少 5 条、规则语法验证 |
| M3 采集归一化 | alert/flow/dns/http/tls 结构化入库，原始事件可追溯 |
| M4 Web | 总览；列表过滤排序分页；详情规则/原始事件/flow/payload；规则启停真实生效 |
| M5 数据自验 | 至少四类攻击和一类正常流量；先写 ground truth；一条命令输出报告 |
| M6 可复现 | 锁定版本，Compose 部署，干净环境复现流程及耗时 |
| M7 自身安全 | 文件大小和路径校验、无 shell 命令拼接、参数化 SQL、payload 转义、无提交密钥、依赖审计 |

## 后续顺序

1. 完善告警列表、详情、总览、规则管理四个必需界面。
2. 扩展为 SYN 扫描、HTTP 爆破、Web 攻击、异常 DNS，加混合正常流量；每类流量有生成脚本和独立 ground truth。
3. 自动评测逐场景 Precision/Recall/F1、总体指标、误报明细、去重率及至少两个变异测试。
4. 明确期望级命中与告警级指标的区别；离线包时间与实际回放处理耗时分别报告。
5. 增加处置审计、聚合及角色权限，随后安全加固、空环境复验、报告与录屏。

## 已接受的部署约束

- 只发布业务端口 80，Nginx 同源转发 `/api`，后端仅内部网络可达。
- SSH 管理通道用于部署，不属于业务公网入口。
- 基础镜像可由用户准备；当前同步脚本自动按提交构建后端，初始化脚本可以拉取基础镜像。新增服务时必须给出所需镜像或调整可复现构建流程，不能假设服务器已有依赖。
- 部署先检查配置与镜像，再 down（保留卷）并 up，等待健康检查。
- Windows 不伪称完成 Linux 引擎验证；真实检测验收在 Ubuntu 执行，用户负责输入凭据。
- 提交、工时、Agent 提示和缺陷记录均按实际发生记录，不能补造跨日历史、检测结果或错误案例。
