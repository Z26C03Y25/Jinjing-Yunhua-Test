# 你只需要照着录视频

录制环境已提前准备，不需要改配置、部署代码、造数据或编写报告。现有公网环境保留；录制使用独立项目jinjing-recording和空业务卷，镜像已有缓存。下面所有操作就是视频内容或开录前的准备。

## 开录前

1. Windows打开PowerShell，执行：

```powershell
ssh -L 127.0.0.1:18080:127.0.0.1:18080 root@123.57.158.71
```

2. 输入服务器密码（不显示字符）。不要关闭此窗口。
3. 浏览器准备打开http://127.0.0.1:18080（启动前无法访问是正常的）。
4. 文件选择器使用D:\code\Jinjing-Yunhua-Test\data。准备web_sqli.pcap和benign_mix.pcap。
5. 打开本地output/pdf/自验报告.pdf作为最终一页报告。关闭无关窗口和通知，确认录音正常。

## 开始连续录制（目标7分钟）

0:00–0:25：展示README架构和终端，说明“独立空业务数据环境，基础镜像已有缓存”。不要说无缓存干净机器。

0:25–1:15：在刚才SSH终端执行：

```sh
cd /root/code/Jinjing-Yunhua-Test/.recording/workspace
make up
```

等待容器健康。目录和密码已准备，不需编辑.env。首次启动后的业务库为空。

1:15–2:00：浏览器访问http://127.0.0.1:18080，分析员登录（使用现有分析员密码），流量检测中上传web_sqli.pcap，等待检测完成。

2:00–3:15：查看告警和详情，加载完整详情、展开原始记录。说明“来源10.0.0.66访问10.0.0.5的HTTP服务，URI包含UNION/SELECT，触发1000001。这是尝试线索，不证明数据库已被攻破”。展示规则、EVE、关联flow与HTTP请求摘要。

3:15–4:00：切换专业视图，填写“报文存在SQL查询注入特征；当前证据不足以确认服务器受损”，建议“核对应用访问日志和数据库日志”。保存，设置已确认（确认此告警线索，不等于确认入侵成功），导出专业和管理报告，展示审计记录。

4:00–4:40：上传benign_mix.pcap，完成后查看无告警结果，说明这是负样本基线，不代表所有正常流量均无误报。

4:40–5:20：规则管理中搜索1000001，查看原文、修改弹窗和历史。不必实际更改规则。展示新增表单的名称和自动编号说明后关闭。

5:20–6:35：回到SSH终端运行：

```sh
make validate
```

按提示输入分析员密码（隐藏输入）。等待本次真实九场景评测输出，说明“六项命中，一个慢扫FN；大小写变异可检出，慢扫低于阈值漏检；精确率与召回率的统计单位已注明”。若本次结果变化按实际解释，不照旧数字念。

6:35–7:00：展示本地一页PDF和agent-log目录，说明缓存启动、HTTP、依赖快照、慢扫等已知限制，结束。

## 录完检查

视频必须5–8分钟、不剪辑、不加速、有声音，包含真实启动、回放、界面告警和自验报告。保存原始MP4，不录明文密码或.env。首录后该项目不再是空数据；如果需要重录空环境，交给Agent处理独立录制项目，不要删除公网业务卷。

不需要你重新整理其他文档。已知限制照实说明即可，不承诺生产级、全部加分项或无缓存15分钟启动。
