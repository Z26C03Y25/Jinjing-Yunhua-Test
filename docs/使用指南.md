# 使用指南

## 当前演示系统

### 两种阅读视角

右上角“阅读视角”可切换，两种视图使用同一数据，只改变展示，不改变账号权限。

- 管理概览：先看中文风险解释、人工研判结论和建议；技术报文默认隐藏。可导出管理风险简报。
- 专业研判：展示原始规则/报文/关联流量，可填写人工结论和处置建议，保存后保留每一版的操作人和时间，再导出专业报告（可编辑 Markdown）。
- 未填写人工研判时，报告明确说明“尚未填写”，不能把自动规则提醒当成已经确认的事件。只读账号可看两种视图和导出，但不能填写结论。

打开 http://123.57.158.71/，更新后可按 Ctrl+F5 清除旧页面缓存。选择“分析员”，输入服务器 `.env` 中 APP_PASSWORD 登录。密码不写在本文档中。

### 第一次体验：正常与攻击对照

1. 左侧“流量任务”中选择本地 `data/web_sqli.pcap`，点击“开始检测”。
2. 点击“刷新任务”，待状态为“检测完成”后点该任务的“查看告警”。
3. 点开告警，点击“加载完整详情”，查看规则原文、协议字段、请求摘要、关联流量及原始事件。
4. 回到“流量任务”，上传 `data/benign_mix.pcap`。完成后该任务应无告警。不要把“尚未完成、暂无告警”当作正常检测结论。
5. “检测总览”查看所有任务累计统计；多次重复检测会累计告警，不是数据造假或重复导入同一任务。

### 分析与规则管理

- 在“告警调查”按源 IP、严重性、状态筛选，选择排序和分页。
- 修改告警处置状态，再重新加载详情，可查操作人和时间。
- “聚合视图”展示按 SID、五元组、任务和十秒桶分组的命中次数，不删除原始证据。
- “检测规则”取消勾选即停用，影响随后开始执行的任务；历史告警保留。演示停用 SID 1000001 后务必恢复，再跑自验。
- 选择“只读用户”时使用 `.env` 的 VIEWER_PASSWORD；未配置时账号禁用。其查看能力相同，所有修改均被后端拒绝。

## 日常部署（Windows）

```bat
scripts\sync-remote.cmd -Deploy
```

输入服务器 IP 和统一密码即可。此模式要求本地私钥口令和 SSH 服务器密码相同；不同密码需调整登录方式，不可误认为任意凭据都能通用。

脚本提交工作区全部未忽略改动、推送、远程快进拉取、按提交构建后端、成功后下架旧容器并启动，最后核对版本和健康状态。运行前检查 git status，避免误提交无关文件。

## 首次交付到另一台 Ubuntu

前置：Docker Engine、Compose（支持 --wait）、git、python3、make、可访问的镜像源；私有仓库有读取权限。克隆仓库后：

```sh
make up
```

首次自动生成分析员/只读随机密码并保存在 `.env`，已有文件不覆盖。云安全组只需给业务放行 TCP80，SSH 管理通道另行限制来源。宿主机80不能被其他服务占用。

```sh
make test
make validate
```

validate 询问分析员密码，回放九份样本，生成 JSON/Markdown 报告。生成的报告会改变仓库工作区，后续开发同步前请保存、提交或复制报告后还原对应工作文件，不要直接覆盖未备份结果。

## 看懂自验结果

- 当前九场景：四类攻击线索、两个正常样本及两种变异。
- 六项期望命中，一项慢扫 FN；当前正常样本零告警。不是“所有攻击都能检测”。

## 故障与安全边界

### 手动编辑检测规则

切换右上角到“专业分析”，进入规则管理，展开“编辑与版本管理”。分析员可以修改单行规则，但必须保留 SID 编号。点击“校验并发布新版本”后，服务器使用真实 Suricata 检查整套规则；失败保持原内容，成功只影响后续开始执行的检测任务。

“查看历史版本与回滚”显示每版内容、操作角色和时间。回滚会先校验，再生成一个新版本，不删除历史记录。多人同时编辑时，旧版本提交会被拒绝，请刷新后核对内容再修改。只读账号不能发布或回滚。

目前没有接入大模型。规则和原始报文保留给分析人员核查，管理视图提供中文解释；中文说明不是攻击成功的证明。请先在样本上验证规则效果，再用于业务流量。

本机 GitHub SSH 22 端口超时，可使用 `scripts\sync-remote.cmd -Deploy -GitHubSshPort 443`。此选项使用官方 SSH 443 入口及已有 GitHub 主机密钥验证，不修改服务器登录端口。

- 连续十次认证失败会按来源限制一分钟，请稍后重试，不要频繁试密码。
- 任务失败：查看错误信息；服务器 `docker compose logs --tail 100`，或 `docker compose exec backend cat /state/任务ID/engine.log`。
- 镜像下载失败：先准备 Debian/Nginx 基础镜像；不要把软件源和 Docker 镜像源混淆。
- 重新部署保留数据卷；`docker compose down -v` 会删数据，不用于日常更新。
- 当前公网80仅 HTTP，适合受限演示，密码并非加密传输。不要用于生产敏感数据。

按 docs/录屏步骤.md 录制真实5–8分钟不剪辑视频；记录实际投入工时；填写姓名、学校/专业、原创性签名和邮件。不要代填或补造时间。

## 规则新增与删除

进入“检测规则”，展开“新增检测规则”，填写完整单行alert规则后点击“校验并新增规则”。SID必须是1000000至2147483647的未使用整数；已归档SID也保留占用，需使用“恢复规则”。引擎校验失败不会保存候选规则。

“删除规则（归档）”将规则退出后续检测，不清理历史任务、规则版本或证据。勾选“显示已归档规则（可恢复）”，可以查看原文、历史和恢复入口。恢复前再次校验整套规则，沿用删除前启停状态（之前禁用的规则恢复后仍禁用）。归档版本不可直接编辑，需要先恢复。只读用户不能新增、修改、归档或恢复。

## 后台表格布局（2026-10-30更新）

侧边栏切换业务模块，左上角按钮收起或展开菜单。规则页上方按名称/SID、状态查询；工具栏“新增”打开校验表单；每行“查看 / 修改 / 启用或停用 / 删除”独立操作。删除需要确认，勾选显示已归档后可恢复。每页10条，搜索和重置会回到第一页。

任务列表以表格展示；点击“查看告警”进入告警表格，再点“详情”打开研判弹窗。详情弹窗右上角可切换阅读视图，关闭后保留列表筛选条件。新增、编辑失败时保留输入，便于修正。

## 登录与模块导航（2026-10-30更新）

打开系统首先进入独立登录页，选择分析员或只读角色并输入密码，支持回车登录。未登录不能看到业务界面。登录后侧边栏按“运行总览 / 流量检测 / 告警研判 / 规则管理”划分模块；不再设置重复的顶部模块页签。模块内上方是查询条件和操作工具栏。

规则模块上方提供新增、修改、删除：修改或删除前先选中一条规则；也可使用对应行内快捷操作。删除仍需确认并采用归档方式。退出登录会清除内存凭据、密码输入和页面已加载数据；刷新页面需重新登录，当前不提供持久登录会话。

## 新增规则的名称与编号

新增时填写“规则名称”和检测条件。后台自动分配SID，无需填写或选择编号；编号在保存成功后展示。已归档编号不重复使用，多个请求由后台串行分配。原文中已有的名称和数字SID会按表单名称及新分配编号替换；编辑既有规则仍保持原编号。

名称只用于识别规则与显示告警，不等于检测条件。需要完整、明确的检测规则；仅填写“SQL注入”等名称无法推断有效检测逻辑。发布前仍需真实Suricata校验。
