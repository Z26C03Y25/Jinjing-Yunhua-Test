# 新服务器自动安装（公开仓库）

这是额外的安装入口，不替代原开发同步脚本。公开GitHub仓库只读拉取不需要GitHub密钥；本地提交/推送仍使用原scripts/sync-remote.cmd及原GitHub SSH认证。

## 你需要准备

- 新Ubuntu服务器已安装并能运行Docker Engine；脚本可尝试自动补装Compose插件。
- root账户可通过SSH密码登录，服务器能访问GitHub、Docker镜像入口及APT源。
- Windows有内置PowerShell和OpenSSH客户端。不要求本地安装Git或配置GitHub密钥。
- 云控制台安全组允许SSH端口和安装结果显示的业务端口（从80开始自动寻找）。脚本可放行已启用的Ubuntu UFW业务端口，但没有云账户权限，不能替你修改云安全组。

## 执行

在下载后的项目目录运行：

```bat
scripts\install-public.cmd
```

也可以直接指定服务器：

```bat
scripts\install-public.cmd -Server 你的服务器IP
```

按顺序完成交互：

1. 输入服务器IP（已指定则不再询问）。
2. 首次SSH连接核对服务器指纹，确认后输入yes。
3. 在SSH的password提示输入服务器密码；输入不显示字符。
4. 设置系统分析员密码并确认两次，至少8字符，输入不回显。
5. 可设置只读账户密码；直接回车则禁用只读账户。

之后脚本自动运行到健康检查和实际登录验证结束。浏览器使用安装结束时显示的实际地址，选择分析员并使用新设密码。80空闲时使用80；80占用则尝试81、82等。

脚本组件为install-public.cmd、install-public.ps1、install-public.sh、install-public.py，四个文件需要保持在同一目录。不需要本地.git目录，也不会执行git add/commit/push。

## 自动执行的工作

- 检查Docker及Compose能力，补装git、python3、make、curl、ca-certificates等基础依赖。
- 通过公开HTTPS地址克隆main到~/code/Jinjing-Yunhua-Test；重复运行仅快进更新，拒绝覆盖已有代码改动。
- 绕开服务器全局Git URL改写，不读取Deploy key，不要求GitHub账户密码。
- 使用HTTP/1.1、超时和有限重试处理GitHub网络中断。
- 准备Debian/Nginx镜像；优先尝试DaoCloud公开入口，失败重试并切换Docker Hub，不修改Docker daemon全局镜像源。
- 构建后端，成功后下架同项目旧容器并重新启动，保留数据卷；等待健康并验证分析员登录。
- 生成不含密码的.runtime-reports/public-install.json。

## 密码与重试

服务器SSH密码由Windows OpenSSH直接读取，不保存到文件、环境变量或Git。系统密码只存在远程进程内存和服务器项目.env（权限600）；不打印到终端，不传入命令行，不提交到Git。临时文件同样受权限保护并清理。

首次写入前检查.env确实被Git忽略且未跟踪；否则拒绝保存。配置校验输出在内存内解析，不将带密码的Compose配置打印。支持常见特殊字符，最终以实际登录验证为准。

重复运行默认保留已有.env和系统密码，不会重设密码或删除业务数据。失败后可以直接重试；如果目录存在非本项目文件、代码改动、端口被其他服务占用时从该端口加一继续寻找，不停止占用者；其他不安全情况会停止。

选中的端口会写回服务器.env，下次继续沿用；属于本项目的运行端口不会被误判为其他服务占用。构建完成、启动前会再次探测。检测同时参考系统监听和Docker端口映射。

当前入口要求root，不自动修改SSH登录策略。网络完全不可达、云安全组未开放或Docker安装本身损坏时，不能承诺靠重试解决；错误会明确显示。不要把“流程自动化”理解为绕过外部网络条件。

如果已经成功下载代码，但重试时GitHub网络中断，可明确加上-UseDownloadedCode，使用服务器现有干净代码继续安装，不查询新版本。默认仍会自动克隆/更新，不静默使用旧版本。

## 参数

默认SSH22、业务80、root、~/code/Jinjing-Yunhua-Test、Compose项目jinjing-yunhua。支持-Port、-RemoteDirectory、-WebPort、-Bind、-Project、-BackendImage，主要用于隔离测试；日常新机安装只需IP及交互密码。

## 验证范围

已在现有Ubuntu服务器的独立目录、项目、镜像名和127.0.0.1:18082端口验证匿名HTTPS克隆、隐藏密码交互、600权限、特殊字符解析、重复运行保留密码、非root容器启动和实际分析员登录。因测试服务器GitHub HTTPS间歇中断，克隆成功后显式复用已下载代码完成后续验证。该服务器已有Docker、基础依赖和镜像缓存，不能据此声称全新空操作系统无缓存安装已实测。

参考：[Docker Compose变量与.env规则](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/)、[DaoCloud公开镜像入口](https://github.com/DaoCloud/public-image-mirror)。

另行执行后端docker build --no-cache，APT重新下载并安装固定Suricata成功，软件包步骤31.6秒。基础镜像已有缓存，因此仍不把它称为全新操作系统完整无缓存验收。

## 外部与内部端口

外部端口从默认80开始递增，可用后持久保存；仅宿主机发布端口改变。容器内Nginx固定监听8080，API通过内部Docker网络访问backend:8000。静态页面直接由Nginx返回，只有/api请求反向代理到后端。

例如选中81：浏览器http://服务器IP:81/ → 宿主机TCP81 → Nginx容器8080 → /api对应backend:8000。本项目需要云安全组放行TCP81，SSH运维端口另保留；不需要开放8080或8000。其他服务占用的80保持不变。

安装成功会打印真实访问地址、应开放的TCP端口、内部转发路径，并写入.runtime-reports/public-install.json。仅127.0.0.1绑定的隔离测试则提示SSH转发，无需公网开放。
