# 交付与运维

## 日常使用

1. 浏览器打开服务器地址，使用分析员密码登录。
2. “检测任务”上传经典PCAP，等待完成，再查看告警。正常样本没有告警是正常结果。
3. “告警研判”筛选并展开记录：管理视图看中文解释，专业视图看原始EVE、规则、协议摘要并填写人工结论。
4. 确认证据后设置处置状态，下载管理简报或专业报告。可疑特征不等于入侵成功。
5. 修改规则在专业视图的“规则管理”；发布前真实校验，版本可回滚。先用样本验证再用于业务数据。

## Windows一条命令更新

```bat
scripts\sync-remote.cmd -Deploy -GitHubSshPort 443
```

中文提示输入IP和统一密码；脚本提交推送、远程拉取、构建、重建容器并等待健康检查。保留数据卷。首次需要准备镜像与GitHub Deploy key；网络无法访问镜像源时不能保证自动解决。

完整独立验收加 `-Acceptance`。独立临时项目使用本机18080及空卷，结束清理临时资源，不删除业务卷。它复用基础镜像缓存，不等于全新无缓存机器验收。

## 备份与恢复演练

```bat
scripts\sync-remote.cmd -Deploy -Backup -GitHubSshPort 443
```

备份会短暂停止后端，未完成任务可能因重启标记失败，需要重新上传。建议先确认没有运行中任务。备份包括数据库、PCAP、EVE、任务规则快照、规则版本和研判审计，不包含服务器.env及SSH密钥。

备份写到服务器项目的 `.runtime-backups/`，权限由umask077保护；逐文件SHA256清单存于归档。隔离tmpfs恢复演练检验每个文件和SQLite完整性，结果为 `.runtime-reports/backup-drill.json`。不要仅因生成了压缩包就认定可恢复。

备份包含敏感报文，需复制到受控的异机加密存储；本脚本不提供自动远程备份、不设置保留期，也不自动删除旧证据或旧备份。管理员需监测空间。磁盘余量不足512MiB或上传大小20倍时拒绝新任务，这不是EVE输出硬性配额。

真正灾备恢复：先在独立空数据卷中执行maintenance.py restore，核对检查结果与任务记录，确认可登录、可查看证据，再由管理员切换卷。恢复程序拒绝覆盖非空目录，不提供清空业务卷按钮。以root恢复后，需将恢复卷文件所有者设为应用UID/GID10001，方可供默认容器写入。密码与SSH配置需单独恢复。不要直接覆盖正在运行的库。

## 故障定位

| 现象 | 处理 |
| --- | --- |
| GitHub SSH超时 | 官方443选项；检查网络，不要跳过主机密钥验证 |
| 上传507 | 空间不足，先备份，由管理员处理容量 |
| 上传429 | 队列满或认证失败过多，等待后重试 |
| 规则422 | 引擎拒绝，旧规则不变；查看校验信息 |
| 规则409 | 内容已更新，刷新核对后重新编辑 |
| 任务failed | 查看错误与engine.log，修复原因后重新上传 |
| 重启后未完成任务失败 | 保留证据并重新提交；当前没有自动续跑 |

## 交付边界

这是可部署的单机离线检测与研判系统，目标为赛题验收及受控试用。单worker与SQLite限制吞吐；没有高可用、多租户、企业身份管理。HTTP80无传输加密，不适合敏感生产公网使用。正式生产前需TLS入口、个人身份、系统包漏洞审计、离机备份管理、容量上限与目标环境压测。

交付前由本人补充：真实5–8分钟不剪辑录屏、实际工时、姓名学校及原创性签名，按题面邮件提交。代码和测试记录不能代替这些人工材料。
