# 已实施的工程决策

以下是 Agent 的实施判断及实际依据，不冒充用户作出的业务判断；最终答辩前需用户理解并确认。

## D1：单机 SQLite，暂不增加数据库服务

选项：SQLite / PostgreSQL。选择前者，降低限时项目部署依赖。事务和 task_id 隔离已测试；代价是写并发和扩容能力有限。

## D2：离线引擎在后端容器内执行

选项：挂载 Docker socket 调度引擎 / 后端镜像包含 Suricata。选择后者，避免给 Web API 宿主机 Docker 控制权限。代价是镜像构建需 apt 源，已实际遇到网络和包仓库问题。

## D3：保留历史规则快照

选项：详情读当前规则 / 每任务保存 active.rules。选择快照，避免启停后无法解释历史告警。远程 API 测试确认启停对新任务真实生效。

## D4：保留慢扫 FN

选项：扩大阈值追求样本全绿 / 保留规则边界并如实报告。选择后者。慢扫真实回放漏检，自动报告计入 FN。后续改进需同时验证正常流量误报，不为演示改写期望。

## D5：单业务入口与内部网络

用户明确要求只暴露 80，采用 Nginx 同源代理、独立入口网络与内部 backend 网络。入口最初仅连接 internal 网络，后补 edge 网络；公网页面已由用户确认可访问。SSH 保留为管理通道。

## D6：构建成功后再停旧服务，核对版本标签

原来只更新 Git 不重建镜像，会出现新页面调用旧 API。改为脚本按提交标签构建后端，再 down/up 和检查运行版本；已在远程真实部署验证。代价是更新期间短暂停机，未实现自动回滚。
